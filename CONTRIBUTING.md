# Contributing to hopforge

hopforge aims to be a community engine for tight-binding physics. Contributions of
models, methods, tutorials, quiz questions and bug reports are very welcome.

## Ground rules
1. **Every physics feature comes with a test against a known result**: an analytic
   formula, a quantised invariant, a sum rule, or a published number. See
   `tests/` for the style (e.g. Chern numbers, conductance steps, Wiedemann-Franz).
2. Keep the public API simple: a function or a method on `Model`/`System`, with
   docstrings that state the formula, units and sign convention.
3. Parallel loops go through `hopforge.parallel.pmap` and accept `n_jobs`.
4. Notebooks are generated by `tools/build_tutorials.py`; edit that file, not the
   `.ipynb`, then run `python tools/build_tutorials.py --execute`.

## Adding a model
Every model in hopforge carries a **reference** and a **benchmark** (a callable that
reproduces a published number). See [`community/`](community/) for a worked example.
```python
import hopforge as hf

def _benchmark():
    m = my_lattice()
    ...
    return published, value, passed

@hf.models.register_model("my_lattice", dim=2, description="...",
                          reference="Author et al., PRL (2026)", benchmark=_benchmark,
                          author="Your Name")
def my_lattice(t=1.0, lam=0.1):
    lat = hf.Lattice(...)
    m = hf.Model(lat, spinful=True, name="my lattice")
    ...
    return m

hf.models.validate("my_lattice")      # must PASS before a pull request
```
Put the file in `community/` (or ship it from your own package through the
`hopforge.models` entry point). `hf.models.validate_all()` runs in CI.

## Development setup
```bash
git clone https://github.com/Gokaran-Shukla/hopforge
cd hopforge
pip install -e ".[notebooks,test]"
pytest -q
```

## Pull requests
* One topic per PR, tests passing (`pytest -q`), new functions documented.
* For performance changes, include a timing before/after.
